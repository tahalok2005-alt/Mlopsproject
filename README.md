# Wine MLOps Demo

A deliberately simple ML project (RandomForest on the UCI Wine dataset, which classifies wines
into three cultivars from 13 chemical measurements) wrapped in a full MLOps scaffold: CI/CD,
Docker, Kubernetes, Terraform (Azure), and Prometheus/Grafana monitoring. The model is a toy; the
plumbing around it is the point.

## Architecture

- **`src/train.py`** — trains a `RandomForestClassifier` on Wine, saves `model/model.pkl`.
- **`src/api.py`** — FastAPI service (`/predict`, `/health`, `/metrics`) for the Docker/K8s/Azure
  deployment path. Instrumented with `prometheus-fastapi-instrumentator`.
- **`app.py`** — standalone Streamlit UI (loads the model directly, no API needed) for a quick
  deploy to Streamlit Community Cloud.
- **`tests/`** — pytest suite for training and the API.
- **`Dockerfile`** / **`docker-compose.yml`** — containerizes the API; compose also spins up
  Prometheus + Grafana locally.
- **`.github/workflows/ci-cd.yml`** — lint, test, build & push image to ACR, then deploy to AKS.
- **`k8s/`** — Deployment, Service (public LoadBalancer), and HorizontalPodAutoscaler manifests.
  Its kustomization also pulls in `monitoring/`, so one `kubectl apply -k k8s/` deploys everything.
- **`terraform/`** — provisions an Azure Resource Group, Container Registry (ACR), and an AKS
  cluster with AcrPull access wired up.
- **`monitoring/`** — Prometheus configs (static for compose, pod discovery for Kubernetes), a
  provisioned Grafana dashboard, and the Kubernetes manifests for both.

## Run it locally

```bash
python -m venv .venv
.venv/Scripts/activate      # or: source .venv/bin/activate
pip install -r requirements-dev.txt
python -m src.train          # trains the model, writes model/model.pkl
pytest -v                    # run the test suite
```

**API:**
```bash
uvicorn src.api:app --reload
# http://localhost:8000/docs for the interactive Swagger UI
```

**Streamlit UI:**
```bash
streamlit run app.py
```

## Run the full stack with Docker Compose (API + Prometheus + Grafana)

```bash
docker compose up --build
```
- API: http://localhost:8000/docs
- Prometheus: http://localhost:9090
- Grafana: http://localhost:3000 (anonymous viewer access enabled; admin/admin to edit).
  The "Wine API" dashboard is auto-provisioned.

## Deploy

### Streamlit Community Cloud
Push this repo to GitHub, then point Streamlit Cloud at `app.py`. No Docker/K8s needed — it
installs `requirements.txt` and `app.py` trains the model itself on first boot if `model/model.pkl`
isn't present (it's gitignored, since it's a build artifact).

### Azure (Terraform + AKS + GitHub Actions)
1. Provision ACR + AKS. ACR names are globally unique, so if `winemlopsacr` is taken, pass another
   project name with `-var project_name=...`.
   ```bash
   cd terraform && terraform init && terraform apply
   ```
2. Create a service principal for CI, scoped to the new resource group:
   ```bash
   az ad sp create-for-rbac --name wine-mlops-ci --role Contributor --scopes /subscriptions/<subscription-id>/resourceGroups/wine-mlops-rg --json-auth
   ```
3. Add these GitHub repo secrets (the last three are `terraform output` values):
   - `AZURE_CREDENTIALS` (the JSON printed by the command above)
   - `ACR_NAME` (`acr_name`)
   - `AKS_CLUSTER_NAME` (`aks_cluster_name`)
   - `AKS_RESOURCE_GROUP` (`resource_group_name`)
4. Push to `main` — CI lints, tests, builds/pushes the image to ACR, then rolls it out to AKS.

Until the secrets exist, `test` still runs but `build-and-push` and `deploy` fail at the Azure
login step.

### Reaching the deployed services
The API gets a public IP. It can take a minute or two to appear:
```bash
kubectl get service wine-api
```
Prometheus and Grafana stay private to the cluster. Use port-forwarding, then open
http://localhost:3000 or http://localhost:9090:
```bash
kubectl port-forward service/grafana 3000:3000
```
```bash
kubectl port-forward service/prometheus 9090:9090
```

## Notes

- `model/` is gitignored — it's a build artifact, regenerated by `python -m src.train` (or at
  Docker build time). Don't commit the pickle.
- Terraform uses sensible small/cheap defaults (`Standard_B2s`, 1 node) — bump `variables.tf` for
  anything beyond a demo.
- Prometheus on Kubernetes stores data in an `emptyDir`, so metrics are lost when its pod restarts.
  Add a PersistentVolumeClaim if you need history.
- Grafana's default `admin/admin` login and anonymous viewing are fine behind port-forwarding. Set
  a real password before exposing it publicly.
