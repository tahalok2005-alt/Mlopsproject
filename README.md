# Wine MLOps Demo

A deliberately simple ML project (RandomForest on the UCI Wine dataset, which classifies wines
into three cultivars from 13 chemical measurements) wrapped in an MLOps scaffold: CI/CD, Docker,
Kubernetes, Terraform, and Prometheus/Grafana monitoring, with the UI deployed on Streamlit
Community Cloud. The model is a toy; the plumbing around it is the point.

## Architecture

- **`src/train.py`** — trains a `RandomForestClassifier` on Wine, saves `model/model.pkl`.
- **`src/api.py`** — FastAPI service (`/predict`, `/health`, `/metrics`) for running in Docker or
  Kubernetes. Instrumented with `prometheus-fastapi-instrumentator`.
- **`app.py`** — standalone Streamlit UI (loads the model directly, no API needed), deployed to
  Streamlit Community Cloud.
- **`tests/`** — pytest suite for training and the API.
- **`Dockerfile`** / **`docker-compose.yml`** — containerizes the API; compose also spins up
  Prometheus + Grafana locally.
- **`.github/workflows/ci-cd.yml`** — lint, test, then build & push the API image to GHCR.
- **`k8s/`** — Deployment, Service (LoadBalancer), and HorizontalPodAutoscaler manifests for any
  cluster. Its kustomization also pulls in `monitoring/`, so one `kubectl apply -k k8s/` deploys
  everything.
- **`k8s-local/`** — overlay for a local kind cluster: uses the local image and adds metrics-server
  so the HPA works.
- **`terraform/`** — creates the kind cluster, loads the image, and deploys `k8s-local/`.
- **`monitoring/`** — Prometheus configs (static for compose, pod discovery for Kubernetes), a
  provisioned Grafana dashboard, and the Kubernetes manifests for both.

## Run it locally

```bash
python -m venv .venv
.venv/Scripts/activate      # or: source .venv/bin/activate
pip install -r requirements-dev.txt
python -m src.train          # trains the model, writes model/model.pkl
pytest -v                    # run the test suite
```

**API:**
```bash
uvicorn src.api:app --reload
# http://localhost:8000/docs for the interactive Swagger UI
```

**Streamlit UI:**
```bash
streamlit run app.py
```

## Run the full stack with Docker Compose (API + Prometheus + Grafana)

```bash
docker compose up --build
```
- API: http://localhost:8000/docs
- Prometheus: http://localhost:9090
- Grafana: http://localhost:3000 (anonymous viewer access enabled; admin/admin to edit).
  The "Wine API" dashboard is auto-provisioned.

The dashboard needs traffic to show anything live, so run the generator while you watch it. It
takes the API URL and defaults to `http://localhost:8001`:
```bash
python scripts/generate_traffic.py http://localhost:8000
```

If port 8000 is busy, set `API_PORT`, for example `API_PORT=8001 docker compose up`.

If the build fails with `invalid file request Dockerfile`, the project is in a OneDrive folder.
Build the image from git instead, then start the stack without building:
```bash
git archive HEAD | docker build -t wine-api:local -
```
```bash
docker compose up --no-build
```

## Run the full stack on local Kubernetes (Terraform + kind)

Needs Docker, `terraform`, `kind`, `kubectl`, and the `wine-api:local` image built above.
```bash
cd terraform && terraform init && terraform apply
```
This creates a kind cluster, loads the image, and deploys the API, HPA, Prometheus and Grafana.
Reach them with port-forwarding, one command per terminal:
```bash
kubectl --context kind-wine-mlops port-forward service/wine-api 8002:80
```
```bash
kubectl --context kind-wine-mlops port-forward service/prometheus 19090:9090
```
```bash
kubectl --context kind-wine-mlops port-forward service/grafana 13000:3000
```
Then open http://localhost:8002/docs, http://localhost:19090 and http://localhost:13000.

Remove the cluster with `terraform destroy`.

## Deploy

### Streamlit Community Cloud
1. Sign in at https://share.streamlit.io with GitHub and choose **Create app**.
2. Pick this repo, branch `main`, and main file `app.py`.

It installs the Streamlit-only `requirements.txt`, and `app.py` trains the model itself on first boot if
`model/model.pkl` isn't present (it's gitignored, since it's a build artifact). Every push to
`main` redeploys the app.

### Kubernetes (any cluster)
Set the image CI pushed to GHCR, then apply. If the GHCR package is private, the cluster also needs
an image pull secret.
```bash
cd k8s && kustomize edit set image wine-api=ghcr.io/<github-user>/wine-api:latest
```
```bash
kubectl apply -k k8s/
```
Prometheus and Grafana stay private to the cluster, so reach them with port-forwarding:
```bash
kubectl port-forward service/grafana 3000:3000
```

## Notes

- `model/` is gitignored — it's a build artifact, regenerated by `python -m src.train` (or at
  Docker build time). Don't commit the pickle.
- Prometheus on Kubernetes stores data in an `emptyDir`, so metrics are lost when its pod restarts.
  Add a PersistentVolumeClaim if you need history.
- Grafana's default `admin/admin` login and anonymous viewing are fine behind port-forwarding. Set
  a real password before exposing it publicly.
